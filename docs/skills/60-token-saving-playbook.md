# Token Saving Playbook

Purpose: Weniger Credits, bessere Ergebnisse.

## Communication Efficiency
- Kurz updaten, dann direkt umsetzen.
- Nur bei echten Unklarheiten nachfragen.
- Nach jeder größeren Änderung kompakt zusammenfassen.

## Search Efficiency
- Erst gezielt nach betroffenen Files suchen, nicht breit alles lesen.
- Wiederverwendbare Patterns identifizieren und konsequent kopieren.

## Edit Efficiency
- Kleine Patches je Datei statt riesiger Umbauten auf einmal.
- Nach 1-3 Dateiänderungen direkt prüfen, statt am Ende 20 Fehler auf einmal zu debuggen.

## Validation Efficiency
- Früh typechecken, vor allem nach Typ- oder Theme-Refactors.
- Regressionsanfällige Screens zuerst kontrollieren.

## Architectural Efficiency
- Datenmodell sauber zuerst, UI danach.
- Für Gruppen/Sessions immer explizite IDs statt impliziter Regeln.
